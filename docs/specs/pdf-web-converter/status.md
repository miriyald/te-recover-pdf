# Status: Client-side PDF to Unicode converter
_Last updated: 2026-10-01_

## Current state
In progress: app works end to end in tests; browser smoke test and docs link remain. Branch `web-pdf-web-converter` (no JIRA ID). Nothing committed.

## Completed
- design.md, plan.md
- Spike (Mahabharatamu.pdf page 6, pdfjs-dist 5.4.149 vs pymupdf):
  - pdf.js yields the same Mac-Roman-decoded glyph characters as pymupdf, so PDF upload is the primary path and paste is the fallback.
  - `getTextContent({ disableNormalization: true })` keeps U+FB01, so no ligature workaround is needed.
  - Item `fontName` is obfuscated; the real name comes from `page.commonObjs.get(fontName).name` after `getOperatorList()`.
- `web/` scaffold (Vite 8.3.2, TypeScript 7.0.2, Vitest 5.0.3, all pinned)
- Ports: `telugu.ts`, `mapping.ts`, `convert.ts`, `profile.ts`, `extract.ts`, `mappings.ts`, `main.ts`, `index.html`
- Mappings are bundled at build time with `import.meta.glob("../../fonts/*/*/mapping.tsv")`, so no copies are committed and the generated shape-naming mapping appears only when it exists.
- Tests (all passing, `tsc --noEmit` clean, `vite build` OK):
  - 120 golden lines generated by `scripts/generate_web_golden.py` (`web/tests/golden.json`, 30KB) match the Python converter.
  - Real PDF page 6 through pdf.js plus the TS converter equals `tests/fixtures/page-6.golden.txt`. The test skips when `files/` is absent.

## In progress
- Browser smoke test of the UI (upload, sample, download, paste)

## Blocked / open issues
- Hosting undecided; defaulting to a local static build (`npm run build`, serve `web/dist`).
- Large PDFs run on the main thread (pdf.js uses its own worker for parsing). A converter Web Worker is deferred until it proves slow.
- `src/anu_unicode/cli.py` and `tests/unit/test_cli.py` have uncommitted edits that are not part of this work; left untouched.
