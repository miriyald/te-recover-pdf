# Plan: Client-side PDF to Unicode converter

## Scope
New `web/` app. No change to `src/anu_unicode` except a small golden-fixture generator under `scripts/`.

## Steps
- [ ] Spike: pdf.js vs pymupdf chars on one Anu page; record in status.md
- [ ] Scaffold `web/` (Vite, TypeScript, Vitest, pinned)
- [ ] Port `telugu.ts`, `mapping.ts`, `convert.ts` with golden tests from Python
- [ ] `profile.ts` and `extract.ts`
- [ ] UI: upload, mapping picker, sample preview, convert, download, paste mode
- [ ] Build script bundling mappings; `.gitignore` for build output
- [ ] Link from `docs/approaches.md`

## Risks & mitigations
- pdf.js hides raw glyph codes: paste mode becomes primary.
- Port drift: golden tests generated by Python.
- Regex and NFC differences: `u` flag, `normalize('NFC')`, covered by golden tests.
- Large PDFs: process in a Web Worker with progress.

## Verification / acceptance criteria
- Vitest golden tests pass; `lint.cmd` and `pytest` stay green.
- Downloaded `.txt` equals CLI output for the same pages and mapping.
- Paste mode gives the same output as the CLI.
- No network requests after load.
